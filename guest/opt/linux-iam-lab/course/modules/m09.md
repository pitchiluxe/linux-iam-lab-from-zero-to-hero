This is the job, end to end. One contractor, four tickets, no step-by-step instructions in the task - just the requirements, like at work. Everything you need was taught in modules 1-8:

| Ticket | You will use |
|---|---|
| CAP-9001 onboard | `useradd`, `chage`, groups (m03), SSH keys (m06), `visudo` (m05), testing as the user (m04) |
| CAP-9002 broken login | logs (m02, m08), StrictModes and sshd diagnostics (m06), account state (m03) |
| CAP-9003 revoke | the leaver procedure (m03), sudo cleanup (m05), key removal (m06) |
| CAP-9004 evidence | reports and evidence (m08) |

## How the capstone works

- Read the current ticket: `lab capstone status` (or the button on the exercise page).
- Do the work in the Linux terminal.
- Run **Check my work** (`lab check m09-capstone`). When the current ticket's requirements are met, the check **records the test results as evidence** and the next ticket arrives.
- CAP-9002 is different for every learner: something will break, and you have to find out what.
- At the end, `lab capstone evidence` generates a signed-off test report from everything that was recorded; you add your own notes.

## A professional's checklist

1. **Read the approval.** Grant exactly what is approved - no more, no "while I'm at it".
2. **Change, then test both directions.** Every allowed action works; every action outside the approval is denied.
3. **Diagnose from evidence, not guesses.** Server logs first, then account state, then file permissions.
4. **Revoke completely.** Password, keys, groups, sudo rules, sessions, scheduled jobs. Keep data and the account for retention.
5. **Leave a trail.** Ticket number in comments and file names; command output in your notes.

`lab capstone status` shows where you are at any time. **Retry exercise** restarts the whole capstone from CAP-9001.
