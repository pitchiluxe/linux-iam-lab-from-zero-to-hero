Access you cannot **see** you cannot govern. This module turns logs into answers and turns repeated checks into scripts that produce evidence.

## Where Linux records identity events

| Source | Contains | Read with |
|---|---|---|
| `/var/log/auth.log` (rsyslog) | logins, `sudo`, `su`, PAM messages, `useradd`/`usermod`, SSH | `sudo grep`, `sudo less` |
| systemd journal | everything above plus service logs, with structured fields | `journalctl` |
| audit log `/var/log/audit/audit.log` | kernel-level audit events: file watches, executed commands, logins | `ausearch`, `aureport` |
| `last` / `lastb` / `lastlog` | login history (`wtmp`), failed logins (`btmp`, sshd only), last login per user | `last -n 10`, `sudo lastb`, `lastlog` |

## journalctl essentials

```linux
sudo journalctl -u ssh --since today --no-pager
sudo journalctl _COMM=sudo --since "2 hours ago"
sudo journalctl -t useradd -t usermod -t userdel -t passwd -t chage
sudo journalctl -p warning -b
```
- `-u UNIT` one service; `_COMM=NAME` messages from a program; `-t TAG` syslog identifier.
- `--since/--until` accept `today`, `"2026-11-11 09:00"`, `"1 hour ago"`. `-b` current boot. `-p` priority.
- `-o short-iso` ISO timestamps; `-o json` for scripts; `--no-pager` to pipe.

Typical lines worth knowing:
```text
pam_unix(sshd:auth): authentication failure; logname= uid=0 euid=0 tty= ruser= rhost=  user=aokafor
sudo:   dpatel : command not allowed ; TTY=pts/1 ; PWD=/home/dpatel ; USER=root ; COMMAND=/usr/bin/cat /etc/shadow
useradd[2311]: new user: name=fgarcia, UID=2010, GID=2010, home=/home/fgarcia, shell=/bin/bash, from=/dev/pts/0
usermod[2400]: add 'btran' to group 'webops'
```

## auditd

The Linux **audit** subsystem records events in the kernel, so they are hard to bypass. Rules:
```text
-w /etc/passwd -p wa -k identity
```
- `-w PATH` watch a file or directory; `-p wa` on **w**rite or **a**ttribute change (`r` read, `x` execute also exist); `-k KEY` a label you search by.
- Persistent rules go in `/etc/audit/rules.d/*.rules`; load them with `sudo augenrules --load`; list active rules with `sudo auditctl -l`.
- Search: `sudo ausearch -k identity -i` (`-i` turns numeric IDs into names, `--start today`). Summaries: `sudo aureport -au` (authentications), `sudo aureport -m` (account modifications), `sudo aureport --summary`.

The audit record shows **auid** - the *original* login user - even after `sudo`, so you can tell that `student` (not "root") changed `/etc/passwd`.

## Scripts that are safe to rerun

An access report runs every month and is evidence, so it must be predictable:
- `set -euo pipefail`; check prerequisites (are we root?) and fail clearly.
- **Read-only**: never change accounts or files you report on.
- Write to a **new, timestamped** file (`report-$(date +%Y%m%d-%H%M%S).csv`) and update a `latest` copy, so reruns never overwrite earlier evidence.
- Quote every variable, handle "no data" without crashing, keep the output format stable (header row, same column order).
- Exit status `0` only when the report is complete.

## Evidence for an access review

Auditors want to know **what** was reviewed, **when**, **by whom**, and that it was **not altered**: the report files, the commands that produced them, a timestamp, and checksums (`sha256sum * > SHA256SUMS`, verified later with `sha256sum -c SHA256SUMS`), packaged together (`tar -czf`).

## Monitoring identity services

If SSSD or the directory stops, nobody can log in - so identity services need **monitoring**, not just logs. Most monitoring systems (Nagios, Icinga, Checkmk, Zabbix agents) run small check programs and read an **exit code** (`0` OK, `1` WARNING, `2` CRITICAL, `3` UNKNOWN) plus one status line, optionally with performance data after `|`. `systemctl is-active NAME` tells you if a service runs; counting `Failed password` lines tells you if someone is guessing passwords. A good check is read-only, runs without root when it can, and offers JSON (built with `jq`) for dashboards.
