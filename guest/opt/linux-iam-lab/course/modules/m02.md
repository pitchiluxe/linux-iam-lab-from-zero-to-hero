An IAM analyst spends a lot of time **answering questions**: who logged in, who failed, who owns these files, which account runs this service. Linux answers them when you combine small commands.

## Redirection: where output goes

| Syntax | Meaning |
|---|---|
| `cmd > file` | write output to a file (**replaces** the file) |
| `cmd >> file` | **append** output to a file |
| `cmd 2> errors.txt` | write error messages (stream 2, *stderr*) to a file |
| `cmd > out.txt 2>&1` | send output and errors to the same file |
| `cmd 2>/dev/null` | throw error messages away |
| `cmd < file` | read input from a file |

## Pipes: chain commands

`cmd1 | cmd2` feeds the output of `cmd1` into `cmd2`. Each command does one small job:

```linux
grep "Failed password" /opt/lab-data/logs/auth-2026-11-10.log | wc -l
```
`grep PATTERN FILE` keeps only matching lines; `wc -l` counts lines. Together: "how many failed passwords?"

| Command | Job | Useful options |
|---|---|---|
| `grep` | keep matching lines | `-i` ignore case, `-v` invert, `-c` count, `-E` extended regex, `-o` print only the match, `-r` recurse into folders |
| `sort` | sort lines | `-n` numeric, `-r` reverse, `-u` unique, `-t: -k3` sort by field 3 split on `:` |
| `uniq` | collapse **adjacent** duplicates (so `sort` first) | `-c` count each |
| `cut` | pick columns | `-d: -f1,7` split on `:` and keep fields 1 and 7 |
| `awk` | pick and test fields | `awk '{print $9}'` prints the 9th space-separated word; `awk -F: '$3>=1000'` |
| `head` / `tail` | first / last lines | `-n 5`; `tail -f` follows a growing file (Ctrl+C stops) |
| `wc` | count | `-l` lines, `-w` words |
| `tee` | show **and** save | `cmd | tee out.txt` |

A classic "top talkers" pipeline:
```linux
grep "Failed password" auth.log | grep -oE 'from [0-9.]+' | sort | uniq -c | sort -rn | head -3
```
```text
     41 from 203.0.113.45
     12 from 198.51.100.7
      3 from 192.0.2.77
```

## Finding files

```linux
find /srv -type f -perm -o+w -ls
```
`find START TESTS ACTIONS`. Tests: `-type f` (files) / `-type d` (folders), `-name '*.csv'`, `-user btran`, `-group finance`, `-nouser` (owner no longer exists), `-perm -o+w` (writable by everyone), `-mtime -1` (changed in the last day). Actions: print (default), `-ls`, `-exec cmd {} +`. Add `2>/dev/null` to hide "Permission denied" noise.

## Processes, services and ports

| Command | Answers |
|---|---|
| `ps aux` / `ps -ef` | every process with its owner (USER column) |
| `ps -o user,pid,cmd -C python3` | processes named python3, chosen columns |
| `pgrep -u btran -l` | processes owned by a user |
| `systemctl status NAME` | is a service running, its main PID, last log lines |
| `systemctl show -p User,MainPID NAME` | one property at a time - script-friendly |
| `systemctl list-units --type=service` | all services |
| `journalctl -u NAME -n 20` | the service's last 20 log lines (`-f` follows, `--since "1 hour ago"`) |
| `ss -ltnp` | listening TCP ports (`-l` listening, `-t` TCP, `-n` numbers, `-p` process; needs `sudo` to see other users' processes) |

## Small Bash scripts

A script is a text file of commands:
```linux
#!/usr/bin/env bash
set -euo pipefail
for u in btran jkim; do
  echo "$u: $(id -nG "$u")"
done
```
- The first line (**shebang**) says which program runs the file.
- `set -euo pipefail`: stop on errors (`-e`), on unset variables (`-u`), and when any part of a pipe fails (`pipefail`). It makes scripts fail loudly instead of doing damage quietly.
- Make it executable with `chmod +x script.sh`, run it as `./script.sh` or put it in `~/bin` (already on your `PATH`).
- Quote variables: `"$u"`, not `$u`.
